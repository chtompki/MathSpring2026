        Though, the code for these three problems also follows as
        \begin{tiny}
        \begin{verbatim}
function [A,rvec,c,a,b,d] = naturalCubicSplines(x,y)
    %%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
    % Natural cubic spline interpolator
    %
    % Inputs:
    %   x     - vector of x data points
    %   y     - vector of y data points
    %   xstar - point(s) where spline is to be evaluated
    %
    % Output:
    %   ystar - spline value(s) at xstar
    %%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%%
    if length(x) < 2 | length(y) < 2
        error('Input vectors are not long enough, please make them of length two or more and be of the same size')
    end
    if length(x) ~= length(y)
        error('Input vectors are not the same length')
    end

    % Make sure x and y are column vectors
    x = x(:);
    y = y(:);

    % n = number of subintervals
    n = length(x) - 1;

    % Initialize A and rvec
    A = zeros(n+1,n+1);
    rvec = zeros(n+1,1);

    % Calculate vector of h values
    h = diff(x);

    % Natural spline boundary conditions
    A(1,1) = 1;
    A(n+1,n+1) = 1;

    % Populate rest of matrix A and RHS vector
    for i = 2:n
        A(i,i-1) = h(i-1);
        A(i,i)   = 2*(h(i-1) + h(i));
        A(i,i+1) = h(i);
        rvec(i)  = 3*((y(i+1)-y(i))/h(i) - (y(i)-y(i-1))/h(i-1));
    end

    % Solve for c coefficients
    c = A \ rvec;

    % Compute a coefficients
    a = zeros(n+1,1);
    for j = 1:n+1
        a(j) = y(j);
    end

    % Compute b and d coefficients
    b = zeros(n,1);
    d = zeros(n,1);

    for j = 1:n
        d(j) = (c(j+1) - c(j)) / (3*h(j));
        b(j) = (a(j+1) - a(j))/h(j) - (h(j)/3)*(2*c(j) + c(j+1));
    end
end
        \end{verbatim}
        \end{tiny}

        \begin{tiny}

coeffs=zeros(length(x)-1, 4);

        At first, we're running \texttt{pp=mkpp(breaks,coeffs)} which takes the intervals over the $x$ vector, and the
        coefficients, and builds cubic polynomials using the values $d_i$, $c_i$, $b_i$, and $a_i$ for the interval between
        $x_i$ and $x_{i+1}$.
        Running \texttt{mkpp} results in the output \texttt{pp} is a matlab struct with the following fields:
        \texttt{form}, \texttt{breaks}, \texttt{coefs}, \texttt{pieces}, \texttt{order}, and \texttt{dim}.
        \texttt{form} seems to be a constant string term with the value $pp$ for piecewise polynomial.
        \texttt{breaks} represents the increasing list of $x$ values of our points.
        \texttt{coefs} is a matrix of coefficients set up for the equation
        \begin{displaymath}
            f(x) = a(x-x_i)^3 + b(x-x_i)^2 + c(x-x_i) + d
        \end{displaymath}
        based on the $i^{th}$ interval.
        \texttt{pieces} is the number of elements in the partition; \texttt{order} is the order of the polynomials; and
        \texttt{dim} is the dimensionality of the target.
        All of this then in turn gets sent to the function \texttt{ppeval(pp,xstar)}, which is a canned matlab function
        specifically for taking this data structure $pp$ and generating $y$ values given an arbitrary collection of $x$
        values.
        We were told to not edit this code, but curiously \texttt{xstar} is not defined, so we must in some fashion by
        defining it.
        It seems the best thing to do here is to take the minimum and maximum values from $x$ and evenly subdivide the
        system for evaluation and to get a plot.
